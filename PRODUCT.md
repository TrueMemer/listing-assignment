# Fieldnotes

Leasing agents manage physical properties and write marketing listings for them. A property owns its address, type, rooms, area and amenities. Each listing owns its title, description, asking price, purpose and review status. A property can have several listings.

The workspace prioritizes repeated operational work. Properties open as a searchable, filterable, paginated table. Cards are an optional view. Listings support manual writing from an empty draft, with optional AI assistance through a separate local Codex adapter. AI suggestions need an explicit apply action.

Server storage owns records and revisions. Changed property facts invalidate listing reviews. Conflicting edits fail visibly. Keyboard navigation, shortcuts and searchable choices support frequent users.

The supplied assignment requires one real AI feature, separate UI/API/domain/integration layers, validation, responsive behavior and human review. The prototype uses synthetic records and does not publish listings. The pilot target remains a Next.js monolith with PostgreSQL and production access controls.

The user's revision asks for daisyUI, simple light and dark themes, typed controls, concise functional labels and functionality before decoration. It rejects slogans, redundant explanatory text and native browser select or dialog widgets. Framework-styled semantic inputs and buttons remain accessible HTML.
